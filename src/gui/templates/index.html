Uses YOLOv8-nano to confirm each moving region is a real target (person, vehicle, animal) before recording, eliminating false triggers from trees, flags, and lighting changes. App version Checks this install's version against the newest one published on GitHub, and can download and install it for you.

Compression Presets
Live Surveillance (Mode 0) Records every frame continuously, 24/7. No footage is ever dropped. Produces the largest files. Use this when you need a complete uninterrupted record (legal evidence, entrance cameras).
Event Recording (Mode 1) Background subtraction runs on every frame. Segments where no motion was detected are discarded entirely. A segment with activity is kept whole. Good balance of coverage vs. storage.
Smart Compress (Mode 2) Encodes the full background frame at low bitrate, but detected object regions (ROIs) are encoded at high quality within the same video. Best for reviewing object detail while saving space.
Object Only (Mode 3) Only the bounding-box patches of detected objects are saved. Background is not recorded at all. Extreme compression. Use only when you care about the objects and not the scene.
Detection Settings
Detection Sensitivity Controls how easily motion is flagged. Low catches only large, obvious movement (fewer false alarms but misses small objects). High flags subtle motion including leaves and lighting changes (catches everything, more false positives). Maps to background subtraction parameters automatically.
Segment Length How many seconds of video go into each output file. Shorter segments (10-30s) are easier to seek through but create many small files. Longer segments (2-5 min) are fewer files but harder to scrub.
BG Subtraction Method MOG2 (Mixture of Gaussians) adapts quickly to gradual lighting changes and is recommended for most scenes. KNN (K-Nearest Neighbours) is more robust to sudden lighting shifts like clouds or flickering. Both are OpenCV implementations running on CPU.
Warmup Frames Number of frames the background model observes before it starts detecting motion. During warmup, everything is treated as background. Set higher (200+) for outdoor scenes with slow-changing lighting; lower (30-60) for static indoor scenes.
AI Super-Resolution Enhancement
Enhancement sharpens detected object regions using a neural network upscaler. It runs in a background thread and only processes 1 out of every N frames to keep the pipeline fast.
Compute Device Auto-detect picks the fastest available option. NVIDIA GPU (CUDA) requires an NVIDIA card with 2+ GB VRAM and PyTorch with CUDA installed; 5-20x faster than CPU. Apple Silicon (MPS) works on M1/M2/M3 Macs only; 2-5x faster than CPU. CPU works on any machine including laptops but is slowest. Phones and tablets are not supported.
SR Model ESPCN / FSRCNN are fast and lightweight, good for real-time use. EDSR gives higher quality but runs slower. Real-ESRGAN gives the best quality and requires the RealESRGAN_x4plus.pth weights file in the models/ folder. See DEV.md for download instructions.
Enhance every N frames SR runs on 1 frame out of every N, then the result is reused for the remaining N-1 frames. N=1 gives the highest quality but can slow the pipeline. N=5 (default) is a good balance. At 25fps you get a fresh SR pass every 0.2 seconds.
Max ROI size (px) SR is skipped on any detection box wider or taller than this value in pixels. Very large boxes get little benefit from SR (the bicubic resize is already fine at that scale) and are expensive to process. 150-250px is the sweet spot.
AES-256 Encryption
How it works Each output segment is encrypted with AES-256-CBC after encoding. The plaintext .mp4 is deleted. Encrypted files have a .enc extension. Key derivation uses PBKDF2-HMAC-SHA256 with 600,000 iterations.
Passphrase Enter a password to derive the encryption key. Keep this safe. There is no recovery without it.
Key File Alternative to a passphrase. Provide a path to a .key file containing raw key bytes. More secure than a password for automated deployments.
Output Segments Table
Target YES means at least one ROI (motion region) was detected in this segment. no means only background, no movement. Mode 1 discards "no" segments entirely.
Motion regions (ROIs) A region of interest - the bounding box around something that moved on a given frame. The "Motion" column counts every motion region across every frame of the clip. A single vehicle passing the camera might produce 50-200 motion regions over its time on screen. Sometimes shortened to "ROIs" in technical context - they're the same thing.
Quality Perceptual sharpness of the detected ROI regions, measured by Laplacian variance. Displayed as an approximate resolution equivalent (~480p, ~720p, ~1080p). Background-only segments show no value.
Storage Saved Estimated compression ratio versus storing the raw uncompressed video. Calculated from segment metadata (resolution, fps, duration) vs. actual file size. A ratio of 20× means the compressed file is 95% smaller than raw.
Hover tooltip Hover over any row to see full metadata: camera ID, exact duration, ROI count, compressed size, estimated raw size, compression ratio, object type, and sharpness score.
Network Access (Teammates)
The server binds to 0.0.0.0 so anyone on the same local network can open the dashboard. No extra setup needed.
Share with team Your LAN URL is shown in the top header. Anyone on the same Wi-Fi or Ethernet network can paste that URL into their browser and view the live dashboard without running the server themselves. Only one person needs to run the server.
Different network? Use a VPN. WireGuard or Tailscale put the remote device on your network, so the dashboard stays private and nothing is published to the internet. Second best is a reverse proxy you control (Caddy or nginx) terminating real TLS, with a strong dashboard password set.
Do not port-forward Do not forward port 5000 on your router, and do not use a public tunnel service. This dashboard serves recorded video of real people and the server speaks plain HTTP, so a forwarded port publishes that footage and replays your password in cleartext on every request. A public tunnel additionally routes all of it through a third party, which defeats the point of self-hosting. If you can reach it from a coffee shop without a VPN, so can everyone else.
Phones / tablets The dashboard works in any modern browser including mobile Safari and Chrome on phones. SR Enhancement GPU acceleration is not available on phones. The pipeline runs on the server's CPU/GPU, not the phone's hardware.
Port 5000 blocked? Start the server on a different port: python run_gui.py --port 8080. Update the LAN URL accordingly.
Demo / Compare and Archive Query
Demo Compare Runs the same input video through multiple compression modes simultaneously and produces annotated side-by-side output with bounding boxes. Useful for showing clients or presentations. Found under Advanced Settings.
Query Archive Search the SQLite metadata database for segments by object type (vehicle, person), camera ID, or time range. The BUSIEST button returns the segments with the most ROI activity. DAILY shows storage used per camera per day.
Live Stream (HLS) Streams an RTSP camera or video file to the browser in real time using HTTP Live Streaming. Latency is ~4-6 seconds. Requires FFmpeg. The annotated overlay shows the active mode label and elapsed time.
Local RTSP Server Downloads and runs MediaMTX (open-source, MIT) locally to create an RTSP endpoint from any video file. Useful for testing the HLS stream or integrating with external NVR software without needing a real IP camera.

Search Tab - Archive Query
Searching clips Use the filters to search your recorded footage by object type, color, scene type, time of day, camera ID, or date range. Press the SEARCH button to run the query. Results appear below with play buttons for each clip.
BUSIEST Shows the 50 most active clips - ordered by number of detected objects. Useful for finding the highest-activity periods quickly.
DAILY SUMMARY Shows total storage and duration grouped by camera and day. Useful for tracking overall usage trends across multiple cameras.
Audio in clips Audio is preserved from source files that have audio (AAC passthrough). Live camera streams and raw webcam input do not carry audio through the pipeline. HLS live stream mode is video-only by design.
Encrypt Tab - File Security
Encrypting a clip Paste or browse to any .mp4 output file. Choose a password or a key file. Click ENCRYPT - the original file is replaced with a locked .enc file that cannot be played without the key. Encrypted clips are moved to the Encrypted/ subfolder in your OneDrive automatically.
Decrypting a clip Browse to an .enc file, enter the same password or key file used when encrypting, and click DECRYPT & PLAY. The clip plays directly in the browser without saving a decrypted copy to disk.
Key files vs passwords Passwords are easier but less secure. Key files are a random 256-bit binary file - more secure for automated systems. Use the GENERATE KEY button to create one. Store the key file separately from the encrypted video.
OneDrive Encrypted folder When OneDrive is detected, encrypted files are automatically placed in OneDrive/SVCS/Encrypted/ so they stay separated from plaintext clips and sync to the cloud.
