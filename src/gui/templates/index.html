SVCS Help & Reference
Compression Presets
Live Surveillance (Mode 0) Records every frame continuously, 24/7. No footage is ever dropped. Produces the largest files. Use this when you need a complete uninterrupted record — e.g. legal evidence, entrance cameras.
Event Recording (Mode 1) Background subtraction runs on every frame. Segments where no motion was detected are discarded entirely. A segment with activity is kept whole. Good balance of coverage vs. storage.
Smart Compress (Mode 2) Encodes the full background frame at low bitrate, but detected object regions (ROIs) are encoded at high quality within the same video. Best for reviewing object detail while saving space.
Object Only (Mode 3) Only the bounding-box patches of detected objects are saved — background is not recorded at all. Extreme compression. Use only when you care about the objects and not the scene.
Detection Settings
Detection Sensitivity Controls how easily motion is flagged. Low — only large, obvious movement triggers detection (fewer false alarms, misses small objects). High — flags subtle motion including leaves, lighting changes (catches everything, more false positives). Maps to background subtraction parameters automatically.
Segment Length How many seconds of video go into each output file. Shorter segments (10–30s) are easier to seek through but create many small files. Longer segments (2–5 min) are fewer files but harder to scrub.
BG Subtraction Method MOG2 — Mixture of Gaussians, adapts quickly to gradual lighting changes. Recommended for most scenes. KNN — K-Nearest Neighbours, more robust to sudden lighting shifts (e.g. clouds, flickering). Both are OpenCV implementations running on CPU.
Warmup Frames Number of frames the background model observes before it starts detecting motion. During warmup, everything is treated as background. Set higher (200+) for outdoor scenes with slow-changing lighting; lower (30–60) for static indoor scenes.
AI Super-Resolution Enhancement
Enhancement sharpens detected object regions using a neural network upscaler. It runs in a background thread and only processes 1 out of every N frames to keep the pipeline fast.
Compute Device Auto-detect picks the fastest available option. NVIDIA GPU (CUDA) — requires an NVIDIA card with 2+ GB VRAM and PyTorch with CUDA installed; 5–20× faster than CPU. Apple Silicon (MPS) — M1/M2/M3 Macs only; 2–5× faster than CPU. CPU — works on any machine including laptops but is slowest. Phones and tablets are not supported.
SR Model ESPCN / FSRCNN — fast, lightweight, good for real-time use. EDSR — higher quality, slower. Real-ESRGAN — best quality, requires the RealESRGAN_x4plus.pth weights file in the models/ folder. See DEV.md for download instructions.
Enhance every N frames SR runs on 1 frame out of every N, then the result is reused for the remaining N-1 frames. N=1 gives the highest quality but can slow the pipeline. N=5 (default) is a good balance — at 25fps you get a fresh SR pass every 0.2 seconds.
Max ROI size (px) SR is skipped on any detection box wider or taller than this value in pixels. Very large boxes get little benefit from SR (the bicubic resize is already fine at that scale) and are expensive to process. 150–250px is the sweet spot.
AES-256 Encryption
How it works Each output segment is encrypted with AES-256-CBC after encoding. The plaintext .mp4 is deleted. Encrypted files have a .enc extension. Key derivation uses PBKDF2-HMAC-SHA256 with 600,000 iterations.
Passphrase Enter a password to derive the encryption key. Keep this safe — there is no recovery without it.
Key File Alternative to a passphrase. Provide a path to a .key file containing raw key bytes. More secure than a password for automated deployments.
Output Segments Table
Target YES — at least one ROI (motion region) was detected in this segment. no — only background, no movement. Mode 1 discards "no" segments entirely.
ROIs Total number of Region-of-Interest detections across all frames in the segment. Higher = more activity. A single vehicle passing might produce 50–200 ROIs.
Quality Perceptual sharpness of the detected ROI regions, measured by Laplacian variance. Displayed as an approximate resolution equivalent (~480p, ~720p, ~1080p). Background-only segments show —.
Storage Saved Estimated compression ratio versus storing the raw uncompressed video. Calculated from segment metadata (resolution, fps, duration) vs. actual file size. A ratio of 20× means the compressed file is 95% smaller than raw.
Hover tooltip Hover over any row to see full metadata: camera ID, exact duration, ROI count, compressed size, estimated raw size, compression ratio, object type, and sharpness score.
Network Access (Teammates)
The server binds to 0.0.0.0 so anyone on the same local network can open the dashboard — no extra setup needed.
Share with team Your LAN URL is shown in the top header. Anyone on the same Wi-Fi or Ethernet network can paste that URL into their browser and view the live dashboard — without running the server themselves. Only one person needs to run the server.
Different network? If your teammate is not on the same local network (e.g. off-campus), they need a VPN or port-forward. Forward TCP port 5000 on your router, or use a tool like ngrok (ngrok http 5000) to get a public URL.
Phones / tablets The dashboard works in any modern browser including mobile Safari and Chrome on phones. SR Enhancement GPU acceleration is not available on phones — the pipeline runs on the server's CPU/GPU, not the phone's hardware.
Port 5000 blocked? Start the server on a different port: python run_gui.py --port 8080. Update the LAN URL accordingly.
Demo / Compare and Archive Query
Demo Compare Runs the same input video through multiple compression modes simultaneously and produces annotated side-by-side output with bounding boxes. Useful for showing clients or presentations. Found under Advanced Settings.
Query Archive Search the SQLite metadata database for segments by object type (vehicle, person), camera ID, or time range. The BUSIEST button returns the segments with the most ROI activity. DAILY shows storage used per camera per day.
Live Stream (HLS) Streams an RTSP camera or video file to the browser in real time using HTTP Live Streaming. Latency is ~4–6 seconds. Requires FFmpeg. The annotated overlay shows the active mode label and elapsed time.
Local RTSP Server Downloads and runs MediaMTX (open-source, MIT) locally to create an RTSP endpoint from any video file — useful for testing the HLS stream or integrating with external NVR software without needing a real IP camera.
